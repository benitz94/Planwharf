## Responsibilities and interfaces

### Execution

The module exports `createExecutionBridge`, `splitSummary`, `repoState`, `readStepTimes`, `appendStepTime`, `readStepOutcomes`, `appendStepOutcome`, `stepOutcomesFile`, `deliveredWithoutVerdict`, and `noVerdictPlan`. Preserve the semantics of each, including input mutation where the bridge updates `store.execution`. Expose an AOT-compatible typed facade that preserves absent versus null values, JSON field names, arrays and order where externally visible. Pure helpers can be static methods; the bridge is a stateful module created once for a store and its injected collaborators.

`createExecutionBridge` receives `store`, `attempts`, `dir`, `rowFor`, `inspect`, `spawnWorker`, `isProcessAlive`, `killWorker`, `models`, `now`, `persist`, `leadId`, and optional `sessionId`, `resolveWorker`, `workerEligible`, `explainNoWorker`, `onRefusal`, `replacement`, `leadLabel` and decision-policy hooks. Its returned operations are `replan`, `propose`, `approve`, `advance`, `appendAddition`, `stop`, `stopWorker`, `resume`, `view`, `find`, `target`, `observe`, `event`, `reconcile`, `paint`, `checkpointForUpdate`, `restore`, `reassign`, `reassignRemaining`, `dropWork`, `answerDecision`, `delegateDecision`. Keep callback invocation order and synchronous persistence points observable. A worker launcher and process liveness/termination adapter are mandatory for dispatch; tests inject controlled adapters and never launch a personal project.

The durable `store.execution` schema contains `megaTasks`, `subTasks`, `results`, `checkpoints`, `timeline`, `decisions` arrays and `observations` object. A MegaTask records project/task/revision IDs, fingerprint, approval and status, exact orchestrator model, timing/deadline, repository before/after, checkpoint, worktree integration, interruption, blockers and next action. A SubTask records identity, type, scope, dependencies, exact assigned/proposed/actual provider and CLI IDs, attempts, result, status, completion and takeover. Results retain structured identity and technical evidence, tests, blockers, file changes, exit and evidence provenance. Checkpoints retain project/MegaTask/job fingerprint, plan revision, repository state and interrupted attempts. Timeline events use stable IDs and optional idempotency keys. Preserve older stored shapes and unknown fields in round trips; do not invent successful evidence from an exit code or an output path.

Approval is only from `READY_FOR_APPROVAL`, rechecks worker eligibility and exact model configuration, and persists authorization/session identity before launch. Proposals require an eligible crew, a linked local folder for implementation, and earlier same-MegaTask dependencies. `replan` and proposal `reassign` require untouched pending steps. Dispatch respects dependency readiness, `MAX_PARALLEL = 10`, quota/refusal policy, exact provider/model IDs, deadlines, worktree scope and the owned attempt record. A worker may be considered delivered without a structured verdict only with exit 0 **and** a new valid commit after start **and** changed files inside its scope. A missing/invalid result cannot become `COMPLETE` merely because the process exited.

Collection validates the result's attempt, MegaTask, SubTask, provider and CLI identity; enforces reported and Git-observed scope without blaming concurrent shared-folder workers; saves the result once; closes the attempt; ticks the work plan when appropriate; appends step time and outcome records, including verify acceptance/fixes, switches and refusals. `noVerdictPlan` is retry-same, then switch, then stop; refusal reroutes are bounded and record quota evidence. Reconciliation after restart must distinguish live, dead, cancelled and already recorded attempts and must never double-collect. Completion requires dependencies and integration to finish. Worktree merging is ordered; a failed integration preserves earlier merged work, exposes the blocker and retains recoverable branches. Cleanup/discard is explicit and refuses running steps.

Stop, worker stop, application-update checkpoint and deadline checkpoint preserve completed results and partial evidence, terminate the owned process tree, pause further dispatch and expose failure if termination does not succeed. Resume selects a checkpoint belonging to the requested project and MegaTask; multiple candidates require explicit IDs. A repository/plan revision mismatch or non-comparable fingerprint returns a reviewable diff and requires explicit `confirmChanges`. A deadline resume explicitly authorizes continued work. Additions enter before Verify, add dependencies for overlapping or unscoped active builds, invalidate/restart Verify, preserve the plan file, and give unique IDs under concurrent requests. Running-step reassignment stops the original worker before changing its exact model, captures a takeover summary and restarts; a failed kill leaves assignment unchanged. Decisions accept owner answers or policy-authorized lead defaults, retain who/when/why, and refuse retroactive edits after dependent work starts.

Dependencies in the current JavaScript are `worker-result`, `project-workspace`, `execution-next`, `provider-adapters`, `project-history`, `provider-refusal`, `time-left`, `step-outcomes`, `worktrees`, `plan-file`, `attempts` callbacks, `node:fs`, `node:path`, `node:crypto`, and bounded Git inspection through child processes. Use the existing C# ports and injectable filesystem/Git/process/clock adapters where they exist. No Node fallback, shell command composition, new NuGet package, dynamic code generation, or host executable is authorized. Preserve the library's `net10.0` and Native AOT warning settings.

### Project home

`engine/project-home.cjs` exports `projectHome`, `compare`, `localGit`. `projectHome(project, snapshot, baseline, options)` builds the home view from the project's latest revision, the matching row, research records, durable MegaTasks/SubTasks/results/timeline/checkpoints and a local Git snapshot. It delegates next action to `execution-next.homeNext` and checkpoint display to `project-history.checkpointDiff` and `execution.repoState`. Return the same `progressDetails`, `resumeTargets`, `actionTarget`, `timelineSummary`, `local`, `current`, `baseline`, `since`, `now`, `running`, `next` and `action` shapes and strings, including durable MegaTask precedence over stale row flags and the relink priority when no folder is linked.

`localGit` uses `linkedWorkspace` and `safeGitWorkspace`, rejects inherited/redirected Git metadata, scopes all Git commands to the canonical linked folder, excludes the configured plan file, suppresses optional locks, renames, external diff/textconv and submodule traversal. Git reads have a 5-second timeout and 8 MiB buffer; untracked fingerprinting caps at 2,000 paths and 8 MiB, checks each parent realpath, and reports unknown rather than a fabricated comparison on failure. Preserve Windows/POSIX path handling, Unicode and symlink/junction containment. `compare` reports added revisions, scoped commits, local edits, new execution results/actions/research, notes and milestone details; when baselines cannot be compared, report `unavailable` rather than a false change count. `recentActions` reads bounded log tails, and `execution` hashes a nonempty result file only after checking its size. These are observation-only operations: inspection must never dispatch work or mutate project source.

Dependencies are `activity.cjs` (`activityMessages`, `workerReport`), `project-history.cjs`, `execution.cjs` (`repoState`), `execution-next.cjs` (`homeNext`), `project-workspace.cjs`, and `orchestrator.js` only for the present `defaultInspect` call in checkpoint display, plus promises filesystem, crypto, path and bounded Git. For Job 45, inject the inspection callback at the home seam so `ProjectHome.cs` does not import or construct the future orchestrator. Preserve the JavaScript default behavior through the caller's adapter and test that the adapter receives the canonical linked folder.
